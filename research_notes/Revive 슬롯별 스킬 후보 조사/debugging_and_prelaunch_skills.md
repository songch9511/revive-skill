## 1. DEBUGGING / UNSTUCK: which skills do real users recommend, and how do the candidates compare?

### Takeaway
`systematic-debugging` from obra/superpowers is the only debugging skill that shows up by name across independent sources, and it is MIT-licensed and physically self-contained, so it is the clear lead for Slot A; `diagnosing-bugs` (mattpocock/skills) and `debugging-and-error-recovery` (addyosmani/agent-skills) are solid MIT alternates. I found no well-evidenced skill for the other half of Slot A (untangling AI slop, stale-dependency upgrades, reviving a broken build): candidates exist but none has real user recommendation behind it.

### Inferences
- Recommended Slot A pick: obra/superpowers `systematic-debugging` (MIT, self-contained, named by independent users). ## 2. PRE-LAUNCH: which skills do real users recommend for verification, code review, and security review of vibe-coded apps?

### Takeaway
No single skill covers verification + code review + security for a vibe-coded app; the realistic Slot B is a small composite. For the security part the best topical fit is raroque/vibe-security-skill (MIT, explicitly checks Supabase RLS, Firebase rules, exposed keys, Stripe webhook signatures) but it has not been committed to since 2026-03-15 and most praise is from its author; the best-maintained heavyweight is cloudflare/security-audit-skill (MIT, 76.7k stars) which is generic rather than vibe-stack-specific and costly to run. For verification, superpowers `verification-before-completion` (MIT, one file) is the obvious pick.

### Inferences
- Built-in `/security-review` reviews "pending changes on the current branch". A revived project whose code is already committed has no pending diff, so the built-in command alone will not audit the existing codebase. Slot B needs a whole-repo audit skill (vibe-security or the Cloudflare skill) in addition.
- Suggested Slot B composition: (1) raroque `vibe-security` vendored (MIT) as the stack-specific checklist for keys, RLS, auth, payment webhooks; (2) superpowers `verification-before-completion` vendored (MIT) as the "prove it works" gate; (3) call the built-in `/security-review` and `/code-review` on the fix diff rather than bundling them. Alternate for a deeper audit: cloudflare `security-audit` in `quick` profile (MIT). Alternates for review/launch checklist: addyosmani `shipping-and-launch` + `security-and-hardening` (MIT), getsentry `security-review` (Apache-2.0 with CC BY-SA reference material).
- vibe-security's staleness (8 months without a commit) matters less than usual because it is static markdown guidance, but its rules will drift from current Supabase/Stripe APIs; Revive would be taking on its maintenance.
- Trail of Bits skills are the most credible author but are aimed at security professionals and are CC BY-SA; they are a poor default for solo vibe coders even though Korean-language recommendations mention them.
- Semgrep's and Snyk's offerings are not bundle candidates: Semgrep's license forbids distribution (see section 4) and no Snyk app-security skill repo was found.

- No Vercel-authored or Supabase-authored pre-launch security checker skill was found in their skill repos; whether such checkers exist elsewhere (e.g. as MCP tools or dashboard advisors) was not researched.

### Inferences
- For solo vibe coders the safest posture is to vendor a few single-purpose markdown skills and invoke them only from Revive's router, instead of installing whole packs with always-on routers. This sidesteps the best-documented complaint class.
- A full Cloudflare audit on a consumer subscription plan is likely to consume a large share of a usage window; if offered, default it to the `quick` profile with an explicit agent budget and tell the user it is partial coverage. No measured token figure was found, so this is a judgement from the design, not data.
- No LLM-only check should be presented as proof the app is safe to take payments; Revive should pair it with deterministic checks (`npm audit`, a secret scanner, Supabase policy listing, a Stripe test webhook with a bad signature).
