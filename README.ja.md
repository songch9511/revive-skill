# Revive

[English](README.md) | [한국어](README.ko.md) | **日本語**

**止まったままのプロジェクトをもう一度動かし、最初の有料顧客まで連れていきます。**

AIで作ってリリースするつもりだったのに、いつの間にか開かなくなったプロジェクトのためのエージェントスキルです。Reviveはリポジトリを読み、なぜ止まったのかを一緒に突き止め、出すのか、小さくするのか、やめるのかをはっきり伝えます。続けると決めたら、知らない誰かがお金を払うまで一緒に作業します。

## こんな人に向いています

- AIコーディングエージェントで何かを作ったが、リリースできていない
- 自分の中ではリリースしたつもりだが、お金を払った人はまだいない
- 完成させる価値があるのかわからず、率直な答えがほしい

こうしたプロジェクトの多くは、コードが壊れたから止まったわけではありません。顧客が見つからない、本当に欲しい人がいるのか自信が持てない、決済の設定でつまずく、いつまでも磨き続けてしまう。止まる理由はたいていこのあたりです。そのためReviveは、直すことから始めません。このプロジェクトにこれ以上時間を使う価値があるかどうかを、先に判断します。

新しいアイデアをゼロから探すためのものではありません。最初の支払いで終わりで、その後の成長は扱いません。

## インストール

[skills CLI](https://github.com/vercel-labs/skills) を使います。

```text
npx skills add songch9511/revive-skill
```

手動で入れる場合は、このリポジトリをクローンして `skills/revive` フォルダをエージェントのスキル置き場にコピーしてください。

```text
Claude Code:  ~/.claude/skills/revive
```

スキルの中身はすべてMarkdownです。次のものがあると、よりうまく動きます。

- **gitの履歴。** 復活させたいプロジェクトにコミット履歴があると、作業がどこで止まったかを読み取れます。
- **サブエージェントを使えるエージェント。** 実装は軽いモデルのサブエージェントに任せ、判断はメインのセッションが行います。サブエージェントがなければReviveが自分で実装します。
- **シークレットスキャナー。** リリース前チェックの一項目で gitleaks などを使います。何かをインストールする前には必ず確認します。

## クイックスタート

止まっているプロジェクトのルートでエージェントを開き、次を実行します。

```text
/revive
```

状況をそのまま伝えても構いません。

```text
去年の春に作ったまま、リリースできていません。完成させる価値はありますか？
```

そのあとの流れは次のとおりです。

1. 質問の前に、まずリポジトリを読みます。何があって何が壊れているかを一緒に見られるよう、アーキテクチャを図にします。
2. 質問は一度に一つです。質問ごとにRevive側の推測も添え、止まった本当の理由について合意できるまで続けます。
3. 判定と推奨を示します。選ぶのはあなたです。
4. 続ける場合は、一件の支払いまでの最短ルートを組み、セッションをまたいで一緒に進めます。

いつ戻ってきても大丈夫です。Reviveはプロジェクト内の `.revive/` フォルダに記録を残し、前回の続きから始めます。

## しくみ

```text
0 偵察 → 1 インタビュー → 2 判定 → 3 最初の支払いまでの道筋 → 4 実行 ⇄ 5 チェックイン → 終了
```

0. **偵察。** まず事実を集めます。最後のコミット、コミットが途絶えた時期、作りかけの機能、ビルドが通るかどうか。そのうえでコード全体を図にし、各部分に「動作する」「未完成」「壊れている」「未使用」を付けます。
1. **インタビュー。** リポジトリで確認した事実をもとに、一度に一つずつ聞きます。挙げられた理由には毎回こう確かめます。*「それが今日解決したら、明日リリースしますか？」* 答えがノーなら、それは原因ではなく言い訳です。
2. **判定。** あいまいにしません。事実、理由、残す価値のあるものを整理し、推奨を一つ出します。そのまま出す、小さくするか方向を変える、やめる、のいずれかです。やめるべきならそう伝え、理由も示します。最終的に決めるのはあなたです。
3. **最初の支払いまでの道筋。** 何を、誰に、いくらで売るのか、何を削るのかを決めます。これ以上作る前に需要を確かめます。機能をもう一か月作るより、実際の人に決済リンクを見せるほうが確かだからです。
4. **実行。** タスクを一つずつ進めます。実装はサブエージェントに渡し、結果はRevive自身がビルドし、動かし、テスト決済をして確かめます。リリース前には、決められたセキュリティチェックに通る必要があります。
5. **チェックイン。** セッションの最初に、いまどこまで来ているかを確認します。一週間進展がなければ手を止め、もう一度理由を聞きます。また止まったのなら、最初の診断が何かを見落としていたということだからです。

終わり方は二つです。知らない誰かから最初の支払いを受け取るか、やめるとはっきり決めて学んだことを書き残すか。どちらも「やり遂げた」と数えます。

## プロジェクトに残るもの

Reviveが把握していることは、すべて `.revive/` にMarkdownで残ります。自分で読んで書き換えることもできます。

```text
.revive/state.md          現在のフェーズ、確認した事実、原因、マイルストーン、顧客の言葉
.revive/architecture.md   コードの図と壊れている箇所
.revive/verdict.md        判定とあなたの選択
.revive/log.md            セッションごとに一行の記録
.revive/checks.md         リリース前チェックの結果
.revive/retro.md          最後に一度だけ書く振り返り
```

## 知っておいてほしいこと

- **わざと率直に言います。** 励ましがほしい場合には向いていません。
- **範囲を小さく保ちます。** 最初の支払いに必要のないことは、書き留めるだけで手を付けません。
- **外の世界に関わることはあなたが行います。** 決済アカウントの開設、本人確認、ドメインの購入、公開の場への投稿、プラグインのインストールは、あなたが行うか承認します。
- **決済はグローバル（米国基準）の販売者を前提にしています。** 基本はStripe、代替はPolarのような販売代行（Merchant of Record）です。国ごとの手続きは対象外です。
- **顧客が目にする文章は英語で書きます。** あなたとの会話はあなたの言語で行います。
- **法律や税務の助言はしません。**

## 一緒に使うとよいスキル

Reviveは単体で動きます。次のスキルが入っていれば、該当する作業でそれを使います。インストールを提案することはありますが、確認なしに入れることはありません。

- UIの作業: [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)
- ランディングページとリリース告知: [marketingskills](https://github.com/coreyhaines31/marketingskills) の `copywriting`、`pricing`、`offers`、`prospecting`、`launch`
- 決済の組み込み: [Stripe](https://github.com/stripe/ai) と [Polar](https://github.com/polarsource/agent-toolkit) の公式スキル
- デプロイ: [deploy-to-vercel](https://github.com/vercel-labs/agent-skills)
